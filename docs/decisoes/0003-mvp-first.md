# ADR 0003 — Execução MVP-first (Eixo 1 completo antes de expandir)

- **Status:** Aceito
- **Data:** 2026-08-20

## Contexto

O curso é grande (~550h, 16 disciplinas). Há risco real de gastar meses *construindo a
plataforma e escrevendo ementas* sem nunca fechar o **loop de aprendizado** — o clássico
"projeto eterno" que nunca entrega valor.

## Decisão

Executar **MVP-first**: primeiro o **esqueleto** (plataforma + PPC + ementas + uma
unidade-referência funcional); depois **completar 100% o Eixo 1** (Fundamentos, Linux/Git,
Python, SQL) com teoria + labs + exercícios + projeto integrador, **antes** de detalhar os
demais eixos. Só então "fanning-out" para os outros eixos.

## Consequências

- ✅ O aluno pode começar a estudar de verdade cedo, com o loop completo validado.
- ✅ Feedback real orienta a autoria dos eixos seguintes (evita retrabalho).
- ⚠️ Os módulos 5–16 ficam como ementas + recursos por um tempo (conteúdo detalhado vem por fase).
